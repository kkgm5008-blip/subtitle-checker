인터뷰 편집 팀 파이프라인을 진행한다. 당신은 **진행자**다. 실제 작업은 서브에이전트 `analyst`(분석팀), `editor`(편집팀), `captioner`(자막팀), `reviewer`(검수팀)에게 Agent 도구로 맡기고, 직접 프리미어를 수정하지 않는다. 사용자는 **대표**라고 부른다.

대표가 함께 적은 내용: $ARGUMENTS

서브에이전트를 부를 때는 매번 작업 폴더 전체 경로와 그 단계에 필요한 값을 모두 적어 준다(서브에이전트는 이 대화를 모른다).

## 0. 준비

1. 작업 폴더를 만든다: `바탕화면\편집작업\YYYYMMDD_HHMM`. 바탕화면은 OneDrive를 쓰면 위치가 다르므로 PowerShell `[Environment]::GetFolderPath('Desktop')`로 찾는다. 같은 이름이 있으면 뒤에 `_2`를 붙인다.
2. 대표에게 작업 폴더 경로를 알리고, 아래 두 가지를 받는다. 받을 때까지 다음 단계로 가지 않는다.
   - **영상 목적**: 누구에게 무엇을 전하려는 영상인지(위에 적은 내용이 있으면 확인만).
   - **원본 SRT 경로**: 편집 전 시퀀스에서 만든 프리미어 자동 캡션. 만드는 법: 창 > 텍스트 → 스크립트 탭 → 시퀀스 트랜스크립션(한국어) → 캡션 만들기 → 캡션 탭 `···` → SRT 파일로 내보내기.
3. SRT 파일이 실제로 있는지 확인한다.

## 1. 분석팀 → 대표 승인

1. `analyst`에게 작업 폴더, 영상 목적, 원본 SRT 경로, (대표가 바꾼 기준이 있으면) 기준값을 넘긴다.
2. 끝나면 `01_분석안.md`를 읽는다. "프리미어 연결 도구 없음", "ffmpeg 없음", SRT 불일치로 멈췄으면 승인을 묻지 말고 이유와 해결 방법을 알리고 멈춘다.
3. 대표에게 요약을 보여준다:
   - 핵심 주제 3줄
   - 원래 길이 → 예상 최종 길이
   - 삭제 표 요약(내용 삭제 단위들은 한 줄씩, 무음·더듬기는 개수와 합계 시간)
   - 확인 필요 목록(번호와 한 줄 설명)
   - 흐름 경고와 주의점
4. 대표의 결정을 받는다. 승인 전에는 **절대 편집팀을 부르지 않는다.**
   - 확인 필요 항목: "삭제할 번호를 알려주세요. 말하지 않은 항목은 남깁니다."
   - 선택: **승인하고 편집 진행** / **고쳐서 다시 분석**(예: "3번 단위는 남겨줘", "-40dB로") / **중단**
5. 확인 필요 결정이나 수정 요청이 있으면 `analyst`에게 그 내용을 그대로 넘겨 분석안을 다시 쓰게 하고, 3~4를 반복한다. 결정만 반영한 경우에는 바뀐 예상 길이만 보여주고 승인을 받는다.
6. 중단이면 지금까지의 결과만 짧게 보고하고 끝낸다.

## 2. 편집팀

1. `editor`에게 작업 폴더를 넘긴다.
2. `02_편집보고.md`를 읽는다. 실패·중단이 있으면 대표에게 알리고 계속할지 묻는다.

## 3. 편집 뒤 SRT 받기

대표에게 요청한다: "편집된 시퀀스에서 자동 캡션을 다시 만들어 SRT로 내보낸 뒤 경로를 알려주세요." (만드는 법은 0단계와 같다.) 경로를 받을 때까지 기다리고, 파일이 있는지 확인한다. 원본 SRT를 다시 주면 타이밍이 안 맞는다고 알려준다.

## 4. 자막팀

`captioner`에게 작업 폴더와 편집 뒤 SRT 경로를 넘긴다.

## 5. 검수팀 (재작업은 한 번만)

1. `reviewer`에게 작업 폴더와 원본 SRT 경로를 넘긴다.
2. `04_검수보고.md` 판정이 **수정 필요**면 문제를 담당 팀별로 묶어, 해당 팀에 **한 번만** 돌려보낸다. 문제 표의 `수정 내용`을 그대로 넘기고, 각 팀은 자기 보고서 맨 아래에 `## 재작업` 섹션을 덧붙인다.
   - 분석팀 문제로 자를 구간이 바뀌면: 분석팀 → (대표 승인) → 편집팀 순서로 한다. 이미 자막 트랙이 들어간 뒤라 자르면 자막도 같이 잘리고, 자막 수정이 필요할 수 있다는 점을 승인받을 때 함께 알린다.
   - 편집팀·자막팀 문제는 각 팀이 바로 고친다.
3. 재작업이 끝나면 `reviewer`를 한 번 더 불러 재검수한다. 재검수에서도 문제가 남으면 더 돌려보내지 않고 남은 문제로 보고한다.

## 6. 최종 보고 (짧게)

- 작업 폴더 경로
- 핵심 주제 3줄
- 길이: 원래 → 최종 (자른 구간 수: 내용 / 무음 / 더듬기)
- 자막: 고친 수, 확인 필요 수
- 검수 판정, 남은 문제(담당 팀과 함께)
- 백업 시퀀스 이름
